# MediaMTX lab (RTSP only)

Viewers talk to **MediaMTX on the Mac Mini**, not to the ESP board.

```
XIAO CameraRTSPWiFi          MediaMTX (Mini)              Colleague / Mini
rtsp://10.128.93.25:554 ──TCP──► pull → cam_xiao ──TCP──► rtsp://10.128.93.23:8554/cam_xiao
         /mjpeg/1                  (MJPEG proxy)              VLC / ffplay
```

No ffmpeg. No HLS / WebRTC in this config. ESP sends MJPEG over Micro-RTSP; MediaMTX re-serves it.

| Host | Role | Typical LabPSK IP |
|------|------|-------------------|
| XIAO Sense | RTSP source (`CameraRTSPWiFi`) | `10.128.93.25` |
| Mac Mini | MediaMTX | `10.128.93.23` |
| Colleague laptop | VLC / ffplay client | any LabPSK client that can reach Mini |

## One-time setup (Mini)

```bash
brew install mediamtx ffmpeg
brew services stop mediamtx   # avoid port fights with lab config
```

Flash the board (USB Mac with arduino-cli):

```bash
./scripts/flash_camera_rtsp.sh /dev/cu.usbmodem101
```

Serial must print:

```text
RTSP: rtsp://10.128.93.25:554/mjpeg/1
```

## Every run (Mac Mini)

**Terminal A** — leave running:

```bash
cd ~/Desktop/ESP32-Experiments-   # or this repo path
pkill -f mediamtx 2>/dev/null; true
XIAO_RTSP_URL=rtsp://10.128.93.25:554/mjpeg/1 ./scripts/mediamtx_run.sh
```

Wait for:

```text
[path cam_xiao] stream is available and online, 1 track (M-JPEG)
```

**Terminal B** — watch on Mini:

```bash
./scripts/watch_xiao_rtsp.sh rtsp://127.0.0.1:8554/cam_xiao
```

## Colleague (LabPSK + VLC)

1. Join **LabHealthSecurePSK** (must reach Mini `10.128.93.23`).
2. Mini must already be running Terminal A above.
3. VLC → **Media → Open Network Stream** →  
   `rtsp://10.128.93.23:8554/cam_xiao`
4. Prefer TCP: Preferences → Input/Codecs → **Live555 stream transport** → **RTP over RTSP (TCP)** → Save → reopen.

**ffplay** (same network):

```bash
ffplay -rtsp_transport tcp rtsp://10.128.93.23:8554/cam_xiao
```

## URLs

| Who | URL |
|-----|-----|
| Board (direct, skip MediaMTX) | `rtsp://10.128.93.25:554/mjpeg/1` |
| Mini local watch | `rtsp://127.0.0.1:8554/cam_xiao` |
| Colleague / LAN | `rtsp://10.128.93.23:8554/cam_xiao` |

Port **8554** = MediaMTX. Port **554** = ESP only (debugging).

## Quality settings (current)

| Setting | Value | Why |
|---------|-------|-----|
| Resolution | VGA 640×480 | Best stable size for Micro-RTSP on LabPSK (SVGA+ often corrupts) |
| JPEG quality | **8** (0–63, lower = sharper) | Clearer than default 10–12 |
| Frame rate | 10 fps | Steady TCP pacing |
| RTP JPEG type | **0** (4:2:2) | Matches OV2640 / `esp32cam-rtsp` |
| Transport | TCP only | LabPSK reliability |
| MediaMTX queue | `writeQueueSize: 4096` | Fewer drops on bursty MJPEG |

Do **not** push UXGA/1080p on this path — Wi‑Fi + Micro-RTSP will tear frames.

## Config notes

[`mediamtx.yml`](mediamtx.yml): `source` filled from `XIAO_RTSP_URL`; TCP pull + TCP viewers; HLS/WebRTC off.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `Connection refused` on `:554` | Board not on `CameraRTSPWiFi` — reflash |
| MediaMTX never goes “online” | Mini can’t reach ESP (LabPSK / wrong IP). Probe: `./scripts/probe_xiao_rtsp.sh` |
| Port 8554 in use | `pkill -f mediamtx` |
| VLC no picture | Force RTP over RTSP (TCP); confirm Mini log shows a reader session |
| `bad vlc` / corrupt JPEG | Board needs current Micro-RTSP (JPEG RTP **type 0**). Reflash from this repo |
| A few “start chunk” lines at join | Normal for MJPEG RTSP; ignore if video then plays |
